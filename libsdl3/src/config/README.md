# SDL_build_config generation maps

`SDL_build_config.h` is generated by the build2 `autoconf` module from
upstream `include/build_config/SDL_build_config.h.cmake` (cmake flavor).

## Platform maps (`subs-*.build`)

Each file defines `config_subs`, a list of `NAME@true|false|value` pairs
applied as `autoconf.substitutions` for that `$c.target.class`. These cover
SDL feature/driver flags and non-header capability bits. No static
`SDL_build_config_<platform>.h` is copied into the build.

| File | Source of the map |
|------|-------------------|
| `subs-macos.build` | CMake-generated config on macOS (SDL 3.4.12) |
| `subs-windows.build` | Upstream `SDL_build_config_windows.h` |
| `subs-linux.build` | Posix HAVE_* baseline + typical Linux drivers |

## System header probes (`apply-system-header-probes.build`)

`HAVE_*` flags that mean "is this system header available?" are **not** in
the subs maps. They are set on the generated header target with:

```
($c.find_system_header("path/to/header.h") != [null])
```

See the C module function `$c.find_system_header(<name>)` (returns path or
`null`). That is how optional deps such as dbus, libudev, libusb, and
Windows SDK headers are detected on the actual host/toolchain.

Regenerate `subs-*.build` when upgrading upstream if feature defaults change.
Prefer more `$c.find_system_header` probes (or project checks under
`build/autoconf/checks/`) over hard-coding new header-backed `HAVE_*` values
in the maps.
